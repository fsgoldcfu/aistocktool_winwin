# 現行短炒系統邏輯與加強說明

> **金融風險提示：此系統是研究與風險管理工具，不是保證獲利或勝率的自動交易系統。** 它最重要的改變是把「沒有值得交易的標的」變成正常輸出，而不是每天硬湊推薦名單。

## 1. 整體設計：三個獨立但共用風險原則的模組

| 模組 | 市場／產品 | 主要用途 | 可以輸出甚麼 |
|---|---|---|---|
| 美股短炒 scanner | 固定美股股票池 | 交易時段內，從候選池找相對活躍且風險回報合格的 long setup | 最多 5 隻、少於 5 隻或零隻 |
| 港股短炒 scanner | 固定港股股票池 | 港股正規交易時段內，用同一套風險原則篩選 long setup | 最多 5 隻、少於 5 隻或零隻 |
| TQQQ 日線模組 | TQQQ | 日線趨勢拉回研究與風險計劃，不會自動交易 | `TRADEABLE`、`WATCH` 或 `NO_TRADE` |

三個模組的共同原則是：資料不可信、風險太大、目標太近或設定未確認時，寧願不給交易建議。

## 2. 美股與港股短炒 scanner：由固定候選池到每日動態推薦

股票池仍然固定，目的是控制資料來源、板塊覆蓋與監察範圍；但是固定池內的每一隻股票不會自動獲得推薦資格。每次掃描會先取得報價、完成日線、ATR、均線、RSI、成交量比率與相對大市表現，然後才逐層篩選。

### 2.1 掃描流程

```text
固定股票池
  ↓
資料品質檢查：價格、OHLCV、日線數量、日期與快取
  ↓
市場時間檢查：只在正規交易時段產生 active signal
  ↓
策略條件：動量／板塊共振／消息或技術覆盤
  ↓
風險計劃：結構阻力、止蝕、最少 1.5R、時間退出
  ↓
Tradeability Score：最低 60/100
  ↓
按分數與風險回報排序
  ↓
最多輸出 5 隻；不足就少於 5 隻，沒有合格則 0 隻
```

### 2.2 Tradeability Score 的含義

Tradeability Score 是「今天這個 setup 是否相對可執行」的硬性篩選與排序工具，**不是勝率預測**。目前滿分為 100，最低通過分為 60。

| 評分項目 | 最高分 | 現行邏輯 | 用途 |
|---|---:|---|---|
| 成交活躍度 | 30 | volume ratio：`≥2x = 30`、`≥1.5x = 24`、`≥1.2x = 16`、`≥1.0x = 8` | 排除成交未有支持的 setup |
| 相對強度 | 25 | 相對大市：`≥2% = 25`、`≥1% = 18`、`>0 = 10` | 優先選擇跑贏指數的股票 |
| 可交易波幅 | 20 | ATR 約在 `1%–4.5%` 得滿分；太靜或太失控都會扣分 | 避免波幅不足或難以控制止蝕的股票 |
| 回報／風險 | 20 | `≥3R = 20`、`≥2R = 15`、`≥1.5R = 10` | 優先選擇目標足以覆蓋初始風險的 setup |
| 市況背景 | 5 | 跌市仍逆市強勢可加 5 分 | 在弱市提高相對強勢股的排序 |

因此，系統不再只按預期毛利或原本策略分數挑選。較高分代表資料顯示該 setup 同時具備成交、相對強度、可交易波幅及足夠 R 倍數；它不代表股價必然上升。

## 3. 每個推薦必須先通過的風險計劃

每個美股或港股推薦不是單純「買入」訊號，而是一份最小可審核的交易計劃。它需要同時有入場參考、結構目標、初始止蝕、R 倍數、時間退出及失效條件。

| 規則 | 現行要求 | 作用 |
|---|---|---|
| 結構目標 | 最近完成日線中必須存在可到達的阻力 | 防止用任意 ATR 目標製造看似有利的推薦 |
| 最低 R 倍數 | 至少 1.5R | 目標不足以補償風險時直接淘汰 |
| 初始止蝕上限 | 不超過入場價 3% | 排除需要過闊止蝕才成立的短炒 setup |
| 美股 time stop | 90 分鐘 | 避免日內交易被無限期拖成持倉 |
| 港股 time stop | 120 分鐘 | 同樣把時間成本寫入規則 |
| 失效規則 | 跌到 initial stop 或時間到即退出 | 令推薦有可預先定義的失敗條件 |

從風險管理角度，這比「判斷方向」本身更重要：它把單次錯誤的損失大小先寫入系統，而不是等到虧損後才決定怎樣處理。

## 4. 市場時間與資料保護

### 4.1 美股

美股 scanner 以 `America/New_York` 判定 09:30–16:00 的正規交易時段，避免因夏令時間而按香港固定時鐘錯位。非交易時段、週末或休市時，系統返回空訊號與市場關閉原因。

美股日線使用 split-adjusted 資料；公開程式碼內的硬編碼資料供應商 key 已移除，改由 Vercel environment variables 提供。資料不足、資料供應商限流或回應無效時，API 以 fail-closed 處理，不會把「沒有資料」錯當成「沒有交易」。

### 4.2 港股

港股 scanner 只在 09:30–12:00 及 13:00–16:00 產生可交易訊號，午休、收市與週末都會返回空結果。日線快取由單純股票代碼改成 `股票代碼:期間`，避免 `1mo` 和 `3mo` K 線被混用；OHLCV 與日期資料不合規時會被拒絕。

港股的相對強度優先使用 quote payload 裡的 `pc`、`preClose` 或 `yc` 作 prior-close 依據，全部不存在才退回開市價。這個 fallback 是相容措施，並不等於已驗證正式數據定義。

## 5. TQQQ 日線模組的邏輯

TQQQ 模組與美港日內 scanner 分開。它只研究強勢日線趨勢中的 pullback，不會因為現價跳動而改寫已完成日線訊號。

| 狀態 | 需要甚麼 | 系統行為 |
|---|---|---|
| `TRADEABLE` | `close > SMA50 > SMA200`、支持區、RSI／布林反轉 trigger 與至少 1.5R 同時成立 | 顯示 entry、止蝕、目標、最長 5 日持有與失效規則 |
| `WATCH` | 有支持區拉回，但反轉未確認 | 只列入等待，不給 order-ready 價格 |
| `NO_TRADE` | 趨勢、支持、目標、止蝕或 trigger 任何一項不合格 | 顯示拒絕原因，不勉強給計劃 |

TQQQ 只使用最後一根完成日線計算 SMA、ATR、RSI、布林通道與 trigger；即時價格只作顯示及時間標記。回測採固定規則，包含 70% 研究／30% 時序 out-of-sample 摘要、每邊 10 bps 成本假設、跳空止蝕以開市價退出，以及目標與止蝕同日觸及時採止蝕優先的保守假設。

## 6. 今次真正加強了甚麼

| 加強項目 | 以前的風險 | 現在的效果 |
|---|---|---|
| 容許零推薦 | 可能為湊名單而展示弱 setup | 沒有合格交易時明確不交易 |
| 交易計劃完整性 | 目標、止蝕與時間退出不一致或缺失 | 每個 active signal 都有 entry、stop、target、R、time stop、invalidation |
| 排序品質 | 高資金／高價股票可能因預期毛利排前 | 先由可執行性分數過濾，再排序 |
| 資料時間點 | 當日未完成 K 線或錯誤 prior close 可扭曲訊號 | 完成日線、日期與 prior-close 定義更嚴格 |
| 資料失敗處理 | 無資料可能被顯示成空訊號或錯誤推薦 | 503／資料狀態與 fail-closed 行為更清楚 |
| 夏令時間與休市 | 美股時間錯位或休市仍有建議 | 正規交易時段 gate 與空訊號說明 |
| 秘密管理 | API key 有機會留在公開 repository | 使用 Vercel environment variables |
| 可驗證性 | 改完規則後缺少最基本回歸檢查 | typecheck、核心風險驗證及 production build 已加入 |

## 7. 仍未解決、不可誇大的地方

系統目前強化的是訊號品質控制與風險定義，沒有證明或保證「勝率變高」。勝率、平均 R、回撤及成本後淨回報仍必須以真實歷史數據和一致的交易級回測確認。

港股仍有兩個重要資料限制。第一，必須在 non-production log 驗證 iTick 的 prior-close 欄位到底是哪一個；第二，現有 `lotSize` 仍未對照每隻股票的真實 board lot，因此可買股數與預期利潤只是概算，未應直接用作下單數量。

另外，短炒的 spread、滑點、佣金、印花稅、交易延遲、消息跳空和 API 資料延遲均可能令實盤結果顯著低於訊號上的理論值。TQQQ 的 3 倍日槓桿則另有波動與跳空風險；它不能被當成一般單倍 ETF。

## 8. 使用方式

每日使用時，先確認資料供應商的 Vercel environment variables 已設定，然後只在正規交易時段掃描。先看合格候選數目與 Tradeability Score，再查看每個候選的 entry、stop、target、R 倍數、time stop 和 invalidation。若系統顯示零隻，正確行為是接受「今日沒有定義清楚的 setup」，而不是手動降低門檻或強迫開倉。

在真正把倉位規模或資金放大之前，應先累積完整 signal log，包括發出時間、入場／出場、實際成交價、費用、滑點、是否按 time stop 退出及市場狀態，再做交易級、成本後、walk-forward 評估。
